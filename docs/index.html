How it works

The graph is the index. The budget is the contract.

Most context tools either dump whole files or strip function bodies until the agent is guessing. CodeGraphy keeps structure, control flow and uncertainty explicit.

01 / BLIND SPOT
[DYNAMIC_LOOKUP]

The AST admits when it can’t see

os.getenv, getattr, importlib and __getattr__ change behaviour at runtime. A static skeleton cannot resolve them. Instead of pretending, CodeGraphy stamps the compressed file with a marker the agent can act on. 

# [DYNAMIC_LOOKUP: os.getenv — static skeleton may
#  miss runtime behavior; inspect full file or
#  get_symbol_body]
def load_settings() -> Settings:
    # ...

The alternative is a clean-looking skeleton that silently drops the only branch that matters.

02 / COMPRESSION
behavioral

Drop the logging. Keep the control flow.

behavioral is not a truncator. It removes prints and logger noise, but keeps if/match branches, raise, return, calls and attribute mutations like self.timeout = .... structural is the smaller fallback. 

- print(f"loading {profile}")
- logger.info("resolving %s", profile)
+ if not token:
+     raise RuntimeError("SERVICE_TOKEN is not set")
+ self.last_profile = profile
+ return Credentials(token=token, ...)

Control flow survives. Noise does not. The agent can still see what the function does.

03 / BUDGET
BM25 + max_tokens

Task-scoped, never over budget.

BM25 ranks entry files from the task description. The compiler expands 0, 1 or 2 hops and stops at max_tokens: 50% for entry files, 80% after the first hop, 100% at the ceiling. No silent overflow. 

"confidence_score": 0.90,
"total_edges": 24,
"resolved_edges": 24,
"missing_dependencies": [
  { "from": "app/cli.py",
    "target": "os.environ[...]",
    "reason": "dynamic_import" }
]

The report is part of the payload, not a log line the agent never reads.

04 / SANDBOX
safe_path + mask_secrets

A sandbox, not a suggestion.

Every read resolves inside the workspace; .. and symlink escapes are rejected. .env, *.pem and *.key are never exposed. sk-, ghp_ and AKIA tokens are redacted before the text reaches the agent.

CI Architecture Linter

Catch the import that shouldn’t exist before it merges.

Tarjan SCC runs in O(V+E). Snapshots are deterministic, so the same graph produces the same JSON on every machine. codegraphy ci-lint is autonomous: no server, no database, exit code 1 on errors, GitHub Actions annotations on stdout.

Deterministic snapshot

Nodes and edges are sorted; each node carries a SHA-256 of the file. No timestamps, no machine paths, no diff noise.

Cycles and layer rules

Tarjan SCC finds cycles in linear time. Forbidden layer dependencies come from codegraphy.yaml.

CI-native output

--format github emits ::error file=…,line=… annotations. Bad input exits with code 2; violations exit with code 1.

No server to keep alive

The linter reads a snapshot and exits. It runs in the same job as your tests, with no hosted service in the loop.

FAQ

          
The questions that decide whether this belongs on your machine.

        


        

          

            Does CodeGraphy work offline?
            

              Yes. Parsing, indexing, context compilation and the MCP server all run locally. Pro activation is also offline:
              the app verifies an Ed25519 signature against an embedded public key and stores the key at
              .codegraphy/license.key. No account, no activation server, no background sync.
            

          


          

            Does my code leave the machine?
            

              Not through CodeGraphy. The agent connects over STDIO on your machine; the graph and source never go to a CodeGraphy service.
              The only network request is a download or update you start yourself. The website uses privacy-friendly page analytics;
              the desktop application does not send code or telemetry.
            

          


          

            How is this different from RAG or embeddings?
            

              RAG retrieves fuzzy chunks by vector similarity. CodeGraphy uses the AST and the import graph, ranks entry points with BM25,
              expands 0/1/2 hops through real dependency edges, and returns source with file and line provenance. There is no vector database
              and no embedding drift. When the static graph cannot resolve something, the payload says so through
              confidence_score and missing_dependencies.
            

          


          

            How do I activate a Pro key?
            

              Request a key, open the desktop app, go to Settings → License, paste the key and activate.
              Verification happens locally and writes .codegraphy/license.key. If the signature is valid, the file limit is lifted
              and the full 16-tool MCP server is enabled. No email login is required.
            

          


          

            What exactly do the three levels keep?
            

              full is the original source. behavioral removes prints and logger calls but keeps branches,
              raises, returns, calls and attribute mutations. structural keeps imports, types, signatures and the first docstring line.
              If a compressed file touches os.getenv, getattr, importlib or __getattr__,
              it is marked [DYNAMIC_LOOKUP] and the agent can call get_symbol_body for the exact body.
